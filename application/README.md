# Flow Memo

Tauri + React 기반 로컬 노트 앱입니다. 블록을 자유롭게 배치하고 무방향 링크로 연결합니다.

## 실행과 검증

아래 명령은 `application` 폴더에서 실행합니다.

```sh
npm install
npm run tauri dev
npm test
npm run build
cd src-tauri
cargo test
```

브라우저 개발 모드(`npm run dev`)는 메모리에서만 동작합니다. 파일 저장과 별도 편집창은 데스크톱 앱에서 사용합니다.

메인 창과 편집창은 각각 마지막 크기·위치·최대화 상태를 앱 공용 설정 폴더의 `ui-state.json`에 기억합니다. 사이드바 너비와 접힘 상태도 공용이며, 플로우나 작업공간을 전환해도 바뀌지 않습니다. 공용 설정이 없을 때만 마지막 활성 작업공간의 `.memo/ui-state.json`을 가져오고, 해당 파일이 없으면 독립 플로우 보관 폴더의 이전 설정을 사용합니다. 이전 설정 파일은 보존합니다. 블록 배치와 캔버스 줌·스크롤은 계속 플로우별 `layout.json`에 저장합니다.

## Flow 요약

데스크톱 앱에서 **이 Flow 요약**을 누르고 확인 창에서 **요약하기**를 선택하면 편집 창의 미전송 내용을 반영하고 파일 저장을 마친 뒤 OpenRouter로 현재 Flow를 요약합니다. 요약 모델 설정은 `openrouter/free`이며, 선택된 Flow 내용은 OpenRouter로 전달됩니다.

처음 사용할 때 OpenRouter API 키를 입력하고 **등록하고 요약**을 누릅니다. 키는 Windows 자격 증명 관리자에 저장되며, 요약 확인 창에서 **저장된 API 키 삭제**로 제거할 수 있습니다. 현재 API 키 저장은 Windows에서만 지원합니다.

완성된 Markdown은 플로우 폴더의 `ai/summary.md`에 하나씩 저장하며, 플로우를 옮길 때 함께 이동합니다. **다시 요약**으로 새 요약을 생성하면 성공 시 기존 파일을 교체하고, 실패 시 기존 요약을 유지합니다. 저장된 요약은 Flow를 다시 열 때 불러오며, **요약 Markdown 보기**를 펼쳐 원문을 확인할 수 있습니다. 요약 입력은 저장을 확인한 시점의 내용이며 이후 편집은 다음 요약에 반영됩니다. 원본 Flow와 블록은 변경하지 않습니다.

OpenRouter 요청의 제한 시간은 5분이며, 저장 실패·인증 실패·빈 응답은 오류로 표시합니다. 입력 크기는 UTF-8 JSON 기준 2,000,000바이트까지입니다. 요약은 연결을 무방향 관계로 취급하며 블록 저장 순서를 인과 순서로 해석하지 않도록 요청합니다.

## 블록과 연결

- 새 Flow를 만들고 캔버스의 빈 공간을 우클릭해 **새 노드 생성**을 누르거나, 캔버스에 포인터를 두고 **Ctrl+T**를 누릅니다. 블록은 자동 연결되지 않습니다.
- 블록을 드래그해 이동합니다. 빈 공간 드래그는 영역 선택, 우클릭 드래그는 패닝입니다.
- 블록을 우클릭해 **연결모드 진입**을 누르거나 **Ctrl+D**로 연결 모드에 들어갑니다.
- 선택된 블록이 하나라면 첫 번째 블록으로 사용합니다. 그렇지 않으면 첫 번째 블록부터 선택합니다.
- 클릭 또는 블록에 포커스를 두고 Enter로 대상을 지정합니다. 두 번째 블록 지정 후 **Enter를 한 번 더** 누르거나 **Ctrl+D**로 연결을 확정합니다.
- 확정하면 연결 모드가 끝납니다. Esc는 연결을 만들지 않고 연결 모드를 종료합니다.
- 연결선을 선택하고 Delete 또는 연결 삭제를 누르면 선만 제거합니다.
- 블록을 선택하고 Delete를 누르면 그 블록과 연결선만 제거합니다. 이웃 블록은 남습니다.

## 저장과 이전 자료 변환

작업공간을 선택하지 않고 **+ 새 플로우**로 바로 시작할 수 있습니다. 독립 플로우는 사용자 홈의 `MemoApp/flows/`에 자동 저장합니다. 작업공간 이름 옆 **+**로 만든 플로우는 해당 작업공간의 `.memo/flows/`에 저장합니다. 사이드바 위에는 독립 플로우, 아래에는 작업공간별 플로우를 표시하며 각 목록을 접고 펼칠 수 있습니다.

두 위치에서 플로우 폴더 구조는 같습니다.

```text
flows/<flow-id>/
  flow.json
  blocks/<year>/<month>/<block-id>.md
  layout.json
  ai/summary.md
```

`flow.json` v2에는 블록 ID와 연결이 들어가고, `layout.json` v2에는 해당 플로우의 위치·크기·줌·스크롤을 저장합니다. 블록 본문과 작업공간 메타데이터는 v1입니다. 사이드바에서 플로우를 다른 작업공간 또는 **독립 플로우**로 드래그하면 확인 후 전체 폴더를 이동합니다. 이동 중에는 메인 화면과 별도 편집창을 잠그고 편집 내용을 저장합니다. 대상 파일을 검증한 뒤 원본을 정리하며, 같은 플로우 또는 블록 ID가 있으면 덮어쓰지 않고 이동을 거절합니다.

이전 `.memo/blocks/`, `.memo/flows/*.json`, 공용 `layout.json`은 열 때 플로우별 폴더로 이전합니다. 이전 root/branches 파일도 모든 깊이의 블록과 기존 화면의 연결을 변환합니다. 마크다운 원문과 기존 요약을 보존하고 원본은 `.memo/backups/pre-graph-.../`에 보관합니다. 변환 결과를 다시 읽어 검증한 뒤 편집과 자동 저장을 시작합니다.

이전 좌표는 브랜치 배치에서의 이동량입니다. 기준 배율 1의 배치와 이동량을 합쳐 변환하므로, 이전 창 크기에서 보이던 정확한 픽셀 위치까지 재현하지는 않습니다.

저장 스냅샷과 이동 작업을 먼저 기록하므로 중단된 저장과 이동은 다음 열기에서 재개합니다. 이동 결과를 확인할 수 없으면 편집과 자동 저장을 멈추고 **이동 결과 다시 확인**을 표시합니다. 이전 앱이 남긴 내용 없는 v1 작업 기록은 자동 복구할 수 없으며, 원본/백업 확인이 필요한 오류로 표시합니다. 지원하지 않는 버전이나 손상된 참조를 빈 데이터로 덮어쓰지 않습니다.

세부 설계는 [구현 계획](../docs/flow_graph_implementation_plan.md)을 참고하세요.
