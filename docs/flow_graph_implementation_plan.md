# Flow를 블록과 무방향 링크로 전환하는 구현 계획

작성일: 2026-09-17. 현재 코드와 사용자 합의를 바탕으로 한 계획이며 구현 완료 보고가 아니다.
기존 `plan.md`는 이전 저장 기능 계획으로 보존한다. 이번 구조 전환에는 이 문서를 적용한다.

## 1. 합의한 동작과 구현 기본값

- root/branch를 없애고 flow의 블록 소속과 링크를 분리한다.
- 링크는 방향이 없다. A—B와 B—A는 같은 링크다.
- 이전 데이터에서 보이던 선은 유지한다. 새 블록에는 자동 연결을 만들지 않는다.
- Ctrl+D 또는 연결 버튼으로 연결 모드에 진입한다.
- 선택된 블록이 하나면 첫 블록으로 사용한다. 없거나 여러 개면 첫 블록 선택을 기다린다.
- 클릭 또는 포커스된 블록에서 Enter로 첫 블록과 두 번째 블록을 지정한다.
- 두 블록 지정 후 별도의 Enter 또는 확인 버튼으로 확정한다.
- 확정 후 일반 모드로 돌아가고 두 번째 블록 하나를 선택 상태로 남긴다.
- Esc/취소는 링크를 만들지 않고 종료한다.

다음은 구현 기본값이다. 기존 기능 범위를 유지하며 별도 확장으로 분리한다.

- 블록은 하나의 flow에만 소속된다. 다른 flow 사이의 링크와 블록 공유는 이번에 추가하지 않는다.
- 고립 블록, 여러 연결 덩어리, 순환 연결을 허용한다. 자기 자신 연결과 중복 연결은 금지한다.
- 블록 삭제는 해당 블록과 그 블록에 붙은 링크만 삭제한다. 이웃 블록을 삭제하거나 자동으로 재연결하지 않는다.
- flow 삭제는 소속 블록·링크·좌표를 함께 삭제하는 기존 소유권 정책을 유지한다.
- 링크 해제는 일반 모드에서 선을 선택한 뒤 삭제 버튼/Delete로 수행한다. 블록 선택과 링크 선택은 서로 배타적이다.
- 연결 모드에서 Ctrl+D를 다시 눌러도 현재 선택을 초기화하지 않는다.

## 2. 저장 계약과 메모리 모델

파일에는 간선 목록을 사용한다. source/target은 양끝의 이름이며 방향을 뜻하지 않는다.

```json
{
  "version": 2,
  "id": "flow_example",
  "title": "메모",
  "blocks": ["A", "B", "C", "D"],
  "links": [
    { "id": "link_1", "source": "A", "target": "B" },
    { "id": "link_2", "source": "B", "target": "C" },
    { "id": "link_3", "source": "A", "target": "D" }
  ]
}
```

- `blocks` 순서는 안정적인 표시/키보드 순회 순서다. 연결이나 좌표를 결정하지 않는다.
- 런타임 Flow는 `id`, `title`, `blockIds: BlockId[]`, `links: Map<LinkId, Link>`로 구성한다.
- WorkspaceState의 블록 본문 Map은 유지한다. 이웃 조회용 Map은 필요할 때 링크에서 파생하며 별도로 저장하지 않는다.
- 무방향 쌍은 두 ID를 정렬한 튜플로 비교한다. 단순 문자열 구분자 결합에 의존하지 않는다.
- Link ID는 생성 후 저장·재로드 과정에서 유지한다.
- Markdown/frontmatter와 workspace는 v1을 유지한다. Flow는 v2, 좌표 의미가 바뀌는 layout은 v2로 구분한다.
- 기존 공통 `STORAGE_SCHEMA_VERSION`을 파일 종류별 버전으로 분리한다.
- 선택, 포커스, 연결 모드, 미리보기는 일시적인 UI 상태이며 저장하지 않는다.

검증 규칙:

- Map 생성 전에 파일 간 중복 Block/Flow ID를 검사하여 덮어쓰기로 누락되지 않게 한다.
- flow 내 블록 ID 중복, 존재하지 않는 본문 참조, 여러 flow 소속, 미소속 본문을 검사한다.
- 링크 ID 중복, 자기 연결, 역순을 포함한 중복 쌍, flow 밖의 끝점 참조를 검사한다.
- activeFlowId는 실제 flow를 가리켜야 한다. 좌표는 유한한 숫자여야 한다.
- 알 수 없는 미래 버전이나 손상된 구조는 조용히 버리거나 빈 작업공간으로 덮어쓰지 않는다.

## 4. 기존 데이터 변환과 저장 안전성

변환은 다음 순서로 진행한다.

1. 모든 파일을 읽고 v1/v2 및 중단된 작업 여부를 판별한다. 이 단계에서는 자동 저장하지 않는다.
2. 기존 트리의 중복/누락 참조를 검증한다. 중복을 Set으로 지워 손상을 감추지 않는다.
3. 모든 깊이의 branch를 순회해 블록을 결정적인 순서로 수집한다.
4. 각 branch의 연속 항목을 링크로 변환한다: `[A,B,C]` → A—B, B—C.
5. 부모 블록과 자식 branch의 첫 블록을 연결한다. 빈 branch에는 선이 없으므로 링크를 만들지 않는다.
6. flow 전체와 layout을 메모리에서 변환하고 블록 집합/기존 화면의 연결 쌍 보존을 검증한다.
7. 변환 전 파일을 별도 백업에 보존하고, 준비된 새 파일과 복구에 필요한 manifest를 기록한다.
8. flow/layout을 교체한 뒤 다시 읽어 검증한다. 성공한 경우에만 변환 완료 및 일반 자동 저장을 허용한다.

백업은 `.memo` 아래의 별도 backups 디렉터리에 두고 blocks/flows 정리 대상에 포함하지 않는다.
branch ID/title 같은 폐기되는 구조 메타데이터도 원본 백업에서 확인할 수 있게 한다.
변환 자체로 Block 본문, ID, 생성·수정 시각을 바꾸지 않는다.

현재 Rust 저장은 파일별 교체만 수행하고 전체 작업의 원자성을 보장하지 않는다. 현재 active-save 표시는 자동 복구 수단도 아니다.
따라서 변환 manifest에는 대상·백업·준비 파일·단계를 기록하고, 재시작 시 같은 작업을 재개하거나 백업으로 되돌릴 수 있게 한다.
복구 완료 전에는 일반 저장과 오래된 파일 삭제를 금지한다. 정상적인 v2를 다시 열 때는 변환하지 않는다.
v1/v2 혼재가 나타나면 manifest와 좌표 버전을 확인하며, 좌표의 의미를 추측해서 재변환하지 않는다.
임시 파일을 본문/flow 파일로 파싱하지 않도록 확장자와 작업 기록에 따라 읽기 대상을 구분한다.

## 5. 좌표와 캔버스 전환

현재 layout의 x/y는 branch의 CSS 기본 배치에 더하는 픽셀 이동량이다. 이를 그대로 절대 좌표로 사용하면 블록이 겹친다.

- v2는 화면 배율과 독립적인 캔버스 기준 좌표를 저장한다.
- v1의 lane 순서, startColumn, 노드 간격 및 기존 이동량을 바탕으로 초기 좌표를 변환한다.
- 기존 배치는 창 너비에 따른 자동 scale과 DOM 치수에도 의존하며 scale은 저장되지 않는다.
  따라서 과거 화면의 정확한 픽셀 위치 복원은 보장할 수 없다. 기준 배율에서 순서·갈래 배치와 이동량을 보존하는 변환 규칙을 고정한다.
- flow 전환/재시작 때 좌표를 다시 자동 정렬하지 않는다. 좌표가 없는 블록만 겹침을 피하는 결정적 기본 위치를 받는다.
- 새 블록은 보이는 영역 또는 선택 블록 주변의 빈 위치에 놓는다. 위치 선택은 링크 생성을 유발하지 않는다.
- 음수 좌표도 접근할 수 있도록 캔버스 원점과 스크롤 범위를 계산한다. 포인터 좌표와 저장 좌표의 변환은 공통 함수로 둔다.
- 노드 이동, 다중 선택 이동, 영역 선택, 우클릭 패닝, 가장자리 자동 스크롤을 유지한다.
- 링크는 임의 방향의 두 블록 경계를 연결하고 화살표 없이 그린다. 기존 오른쪽→왼쪽 고정 곡선 계산을 교체한다.
- 링크 클릭 영역과 빈 캔버스 영역 선택 이벤트가 충돌하지 않게 한다.

## 6. 연결 모드 상태와 이벤트

연결 상태는 `idle`, `awaitingFirst`, `awaitingSecond(firstId)`, `ready(firstId, secondId)`로 명시한다.
flowId를 함께 보관하여 다른 flow로 상태가 넘어가지 않게 한다.

| 현재 상태 | 입력 | 결과 |
| --- | --- | --- |
| idle | Ctrl+D/연결 버튼 | 유효한 단일 선택이 있으면 awaitingSecond, 아니면 awaitingFirst |
| awaitingFirst | 블록 클릭/포커스 블록 Enter | 첫 블록 지정, awaitingSecond |
| awaitingSecond | 다른 블록 클릭/포커스 블록 Enter | 두 번째 블록 지정, ready |
| ready | 다른 블록 클릭 | 두 번째 블록 교체 |
| ready | 별도 Enter/확인 버튼 | 재검증 후 링크 생성, idle, 두 번째 블록 선택 |
| 연결 모드 전체 | Esc/취소 | 링크 생성 없이 idle |

- 첫 블록과 두 번째 블록을 시각적으로 구분하고 ready 상태에서 점선 미리보기를 표시한다.
- 같은 블록이나 이미 연결된 쌍은 확정하지 않고 상태 안내를 표시한다. 확정 직전 도메인에서도 다시 검증한다.
- 두 번째 블록을 지정한 Enter는 같은 이벤트에서 확정까지 진행하지 않는다.
- key repeat와 이벤트 버블링, 버튼의 기본 Enter click으로 링크가 중복 생성되지 않게 한다.
- Tab으로 블록과 확인/취소 버튼에 접근할 수 있게 하고, 블록 선택 후 포커스를 유지한다.
- 입력 요소와 본문 편집 중에는 캔버스 단축키를 처리하지 않는다. Ctrl+D를 처리한 경우 기본 동작을 막는다.
- 연결 모드의 블록 클릭은 편집창을 열지 않는다. 제목 입력 영역도 연결 대상을 선택할 수 있도록 모드별로 렌더링한다.
- 연결 모드에서는 블록 드래그와 영역 선택을 잠시 비활성화하고 패닝은 유지한다.
- flow/작업공간 전환, 삭제 등으로 대상이 사라지면 미리보기와 연결 상태를 정리한다.
- 미리보기는 링크 Map에 넣지 않는다. 취소·미확정 상태는 저장되지 않는다.

## 7. 앱 상태·편집창·저장 연동

- `selectedBlockIds`, 기존 `workspace.selectedBlockId`, 키보드 포커스를 구분하고 선택의 기준을 하나로 정리한다.
- 블록 삭제 시 링크·좌표·선택·연결 대상과 해당 편집 세션을 함께 정리한다.
- 편집창 저장 요청에는 작업공간/세션 식별자를 포함하여 삭제된 블록이나 이전 작업공간으로부터의 늦은 요청을 거절한다.
- 제목/본문 수정은 그래프 구조를 건드리지 않는다. 일반 모드의 편집창 사용 흐름은 유지한다.
- 자동 저장, 재시도, 변환 저장은 동일한 직렬 저장 경로를 사용한다. 현재 retrySave의 큐 우회를 없앤다.
- 저장 전 검증 실패 시 파일 교체와 정리를 시작하지 않는다.
- 저장 요청은 작업공간과 수정 세대를 묶어 관리한다. 예전 저장 완료가 최신 편집을 저장 완료로 표시하지 않게 한다.
- 작업공간 전환 및 종료에서 진행 중 저장/대기 변경을 처리하고, 실패 시 메모리 상태를 보존한다.
- 현재 전체 스냅샷 저장 방식은 유지한다. 파일별 dirty 최적화는 이번 전환의 필수 조건으로 삼지 않는다.

## 8. 구현 순서와 단계별 완료 기준

1. **새 계약과 변환 fixture**: v1 입력 및 기대 blocks/links를 작성하고 버전·삭제·좌표 규칙을 고정한다.
2. **도메인 교체**: createBlock/connectBlocks/disconnectBlocks/deleteBlock/deleteFlow와 검증을 구현한다.
   고립 블록·순환을 허용하며 삭제가 이웃에 전파되지 않는 테스트가 통과해야 한다.
3. **직렬화·변환·파일 복구**: v2 round-trip, v1 변환, 좌표 변환, 백업과 중단 복구를 구현한다.
   읽기/검증에 실패한 작업공간을 자동 저장으로 덮어쓰지 않는 것이 완료 조건이다.
4. **캔버스와 기존 호출부 교체**: flat blocks/links 렌더링, 자유 좌표, 사이드바, 추가/삭제, 편집창 및 문구를 바꾼다.
   새 모델로 생성·편집·이동·삭제·저장·재로드가 동작해야 한다.
5. **연결 모드와 링크 해제 UI**: 상태 전이, 클릭/Enter, 미리보기, 확정/취소, 선 선택/삭제를 구현한다.
6. **통합 검증과 정리**: 저장 경쟁, 작업공간 전환, 실패 복구 및 데스크톱 입력을 검증하고 구 트리 의존성을 검색한다.

각 단계는 테스트 가능한 단위로 진행하되, 전체 전환이 끝나기 전 중간 버전을 실제 사용자 데이터에 적용하지 않는다.
현재 작업 트리에 있는 `application/src-tauri/Cargo.toml` 변경은 기존 사용자 변경으로 보존한다.

## 9. 검증 계획

현재 App.test는 사이드바 너비만, FlowCanvas.test는 계산 도우미만 테스트한다. 실제 UI 이벤트 검증을 추가한다.
순수 상태 전이 테스트에 더해 DOM 테스트 환경에서 클릭/키보드/포커스/버블링을 확인한다.

| 영역 | 핵심 사례 |
| --- | --- |
| 도메인 | 고립 블록, 순환/분리 그래프, 역순 중복, 자기 연결, 다른 flow 끝점, 이웃 보존 삭제 |
| 변환 | 빈 root, 연속 블록, 여러 자식 branch, 깊은 중첩, 빈 branch, 손상 참조, 누락 없는 블록/선 보존 |
| 직렬화 | v2 round-trip, 링크 ID/본문/시각 보존, 버전 분리, 중복 ID 덮어쓰기 방지 |
| 좌표 | 기존 offset 변환, 누락 좌표, 음수 좌표, 이동 후 재시작, 창 크기 변경에도 좌표 불변 |
| 연결 UI | 기존 단일 선택/무선택/복수 선택 진입, 클릭/Enter 조합, 별도 확정, 길게 누른 Enter, 취소 |
| 이벤트 경계 | 제목 입력, Tab 포커스, 버튼 Enter, 삭제, flow 전환, 기존 링크 선택과 영역 선택 충돌 |
| 편집창 | 본문 수정 유지, 삭제된 블록 저장, 이전 작업공간 세션 저장 요청 차단 |
| 저장/복구 | 큐와 재시도, 연속 편집 최신 상태, 백업 실패, 변환 단계별 중단, 재개/복원 후 재로드 |

자동 검사: `npm test`, `npm run build`, Rust 변경에 대한 `cargo test`/컴파일 검사.
임시 작업공간으로 실제 Tauri 생성→연결→취소→삭제→이동→종료→재실행을 확인한다.
기존 데이터 사본을 변환해 블록 ID 집합, 본문, 연결 쌍이 변환 전 기대값과 일치하는지 확인한다.

최종 완료 조건은 root/branch가 v1 변환 전용 코드 밖에서 필요하지 않고, 사용자가 확정한 무방향 링크와 블록 좌표가 재시작 후 유지되는 것이다.
